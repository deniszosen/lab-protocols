# Contributing

Lab members and outside readers are welcome to suggest improvements.

## Ways to help

- **Report an error or a gap.** Open an issue with the protocol number, the step and what you found. If you checked a value against the source paper or the manufacturer's manual, say so.
- **Add what you learned from a pilot.** When you run a protocol, record what worked, what you changed and why. Send it as a pull request that adds a dated "Lab notes" section, or as a new version.
- **Add a new protocol.** Copy [templates/protocol-template.md](templates/protocol-template.md), use the next free number and add the protocol to the index in the README.

## Rules

1. **Do not change a number from a paper silently.** If you think a unit, a concentration or a catalogue number is wrong, write what the paper prints, say what you think it should be and mark it as unverified (see [docs/gaps-to-confirm.md](docs/gaps-to-confirm.md)).
2. **Keep "from the paper" and "general practice" apart.** Label anything you add from experience.
3. **No confidential material.** Do not add unpublished data, patient information, participant identifiers, credentials or anything covered by an agreement with a funder or collaborator.
4. **Safety and ethics first.** Every protocol that involves animals, human material, hazardous chemicals or genetically modified organisms must say which approval or risk assessment is needed.
5. **Plain language.** Short sentences, numbered steps, one action per step, units on every number.

## Versions

Increase the version in the header table and add one line to the changelog in your pull request. The PI reviews and merges.

For conduct, data handling, authorship and safety rules, see the [Zosen Lab handbook](https://github.com/deniszosen/lab-handbook).
